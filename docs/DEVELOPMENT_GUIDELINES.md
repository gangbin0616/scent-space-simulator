# 개발 가이드라인

## 절대 원칙

- `src/floorplan.js`를 도면의 단일 진실 공급원으로 유지합니다.
- 시뮬레이터와 2.5D 뷰어가 서로 다른 도면 데이터를 가지면 안 됩니다.
- `FLOORPLAN_SPEC.md`와 다른 모양으로 벽을 다시 그리지 않습니다.
- 특히 곡선 벽을 임의의 동심원 구조처럼 바꾸면 안 됩니다.
- 외부 이미지를 hotlink하지 않습니다. 필요한 자산은 `src/assets/`에 로컬 파일로 둡니다.

## 코드 구조

- `src/floorplan.js`: 도면 좌표, 벽 판정, 벽 라인 추출
- `src/simulation.js`: 향 확산 엔진, source별 field/buffer, 샘플링
- `src/app.js`: 화면 상태, Canvas 렌더링, UI 이벤트
- `src/styles.css`: 앱 레이아웃과 컨트롤 스타일

## 시뮬레이션 규칙

- source는 각각 다른 향입니다.
- source별 `emission`, `spread`, `decay`는 독립적으로 계산합니다.
- target 샘플링은 전체 농도와 source별 농도를 모두 반환해야 합니다.
- 벽, 곡선 벽, 하단 블록, 동적 가벽은 향이 통과할 수 없습니다.
- 장치 효과를 추가할 때도 mask를 무시해서 향을 이동시키면 안 됩니다.

## UI 규칙

- 시뮬레이터는 데스크톱에서 작업 앱처럼 보여야 합니다.
- 설계도 맵이 주 작업면이고, 설정은 왼쪽 패널에 모읍니다.
- 리스트가 길어질 때 전체 페이지를 끝없이 늘리지 말고 패널 내부 스크롤을 씁니다.
- 버튼은 짧고 명확한 동사로 표시합니다.
- 현재 선택된 출발점, 도착점, 장치는 캔버스와 패널 양쪽에서 알아볼 수 있어야 합니다.

## 검증 체크리스트

변경 후 최소한 아래 명령을 실행합니다.

```powershell
node --check src\floorplan.js
node --check src\simulation.js
node --check src\app.js
```

브라우저에서 확인합니다.

- `http://127.0.0.1:4173/#viewer`
- `http://127.0.0.1:4173/#simulator`

확인할 항목:

- 뷰어 드래그 시 시야가 회전하는가
- 미니맵이 현재 위치와 방향을 표시하는가
- 출발점과 도착점이 각각 최대 10개에서 멈추는가
- 향별 색상과 농도 막대가 일치하는가
- 서큘레이터 흡입/토출이 보이는가
- 온열/냉각 움직임이 보이는가
- 향이 벽을 통과하지 않는가
